설계 포인트

  1. 1Internal ALB 만 둔다. 포인트 API 는 주문 · 결제 서비스가 호출하는 내부 서비스이므로 인터넷에 노출하지 않는다. 관리자도 사내망 / VPN 으로 접근한다.
  2. 2태스크를 늘려도 안전하다. 동시성 제어를 애플리케이션 메모리가 아닌 DB 행 락(point_account FOR UPDATE)으로 하고, 재시도는 requestId 로 멱등 처리하므로 태스크 수와 무관하게 정합성이 유지된다.
  3. 3잔액 조회와 변경은 Writer 에서만 한다. Reader 는 복제 지연이 있어 방금 적립한 포인트가 보이지 않을 수 있다. Reader 는 장애 대비와 이력 조회에만 쓴다.
  4. ·두지 않은 것: 만료 배치(EventBridge) — 만료는 expires_at 과 현재 시각으로 판정한다. 잔액 캐시(ElastiCache) — 잔액은 Lot 합계로 계산하며 캐시하지 않는다.
