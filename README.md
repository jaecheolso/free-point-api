## 과제 설명
무료 포인트 시스템(API) 구현. 개발 환경: Java 21, Spring Boot 3.5.16, H2 2.3.232

### 필요 기능
1. 적립
   1. 1회 적립가능 포인트는 1포인트 이상, 10만포인트 이하로 가능하며 1회 최대 적립가능 포인트는 하드코딩이 아닌 방법으로 제어할 수 있어야 한다.
   2. 개인별로 보유 가능한 무료포인트의 최대금액 제한이 존재하며, 하드코딩이 아닌 별도의 방법으로 변경할 수 있어야 한다.
   3. 특정 시점에 적립된 포인트는 1원단위까지 어떤 주문에서 사용되었는지 추적할 수 있어야 한다.
   4. 포인트 적립은 관리자가 수기로 지급할 수 있으며, 수기지급한 포인트는 다른 적립과 구분되어 식별할 수 있어야 한다.
   5. 모든 포인트는 만료일이 존재하며, 최소 1일 이상 최대 5년 미만의 만료일을 부여할 수 있다. (기본 365일)
2. 적립취소
   1. 특정 적립행위에서 적립한 금액만큼 취소 가능하며, 적립한 금액 중 일부가 사용된 경우라면 적립 취소될 수 없다.
3. 사용
   1. 주문시에만 포인트를 사용할 수 있다고 가정한다.
   2. 포인트 사용시에는 주문번호를 함께 기록하여 어떤 주문에서 얼마의 포인트를 사용했는지 식별할 수 있어야 한다.
   3. 포인트 사용시에는 관리자가 수기 지급한 포인트가 우선 사용되어야 하며, 만료일이 짧게 남은 순서로 사용해야 한다.
4. 사용취소
   1. 사용한 금액 중 전체 또는 일부를 사용취소 할 수 있다.
   2. 사용취소 시점에 이미 만료된 포인트를 사용취소 해야 한다면 그 금액만큼 신규적립 처리한다.

### 예시
1. 1000원 적립한다 (총 잔액 0 -> 1000원) — pointKey : A
2. 500원 적립한다 (총 잔액 1000 -> 1500원) — pointKey : B
3. 주문번호 A1234 에서 1200원 사용한다 (총 잔액 1500 -> 300원) — pointKey : C
   - A 적립에서 1000원 사용 -> A의 사용가능 잔액 1000 -> 0
   - B 적립에서 200원 사용 -> B의 사용가능 잔액 500 -> 300
4. A의 적립이 만료되었다
5. C의 사용금액 1200원 중 1100원을 부분 사용취소 한다 (총 잔액 300 -> 1400원) — pointKey : D
   - A는 이미 만료되었으므로 pointKey E 로 1000원이 신규적립된다.
   - B는 만료되지 않았으므로 사용가능 잔액 300 -> 400원이 된다.
   - C는 이제 1200원 사용금액 중 100원을 부분취소 할 수 있다.

### 설계 참고
- 테이블 간 물리 FK는 설정하지 않았다. 관계는 논리적으로만 두고(`schema.sql` 각 테이블 주석의 "논리 FK" 참고) 참조 무결성은 애플리케이션에서 보장한다.
  - 운영 환경(Aurora MySQL)에서의 샤딩·온라인 DDL·데이터 이관 유연성을 고려했다.
  - InnoDB는 자식 행 INSERT 시 부모 행에 공유 락을 걸기 때문에, 동시성 제어용으로 잠그는 `point_account` 행에 의도치 않은 락이 추가되는 것을 피했다.
  - 금액 정합성(음수 금지, 초과 취소 금지, 멱등 키)은 CHECK / UNIQUE 제약으로 DB에서 강제한다.

## 빌드 및 실행
요구사항: Java 21

```bash
./gradlew build     # 빌드 + 테스트
./gradlew bootRun   # 실행 (http://localhost:8080)
```
- Swagger UI: http://localhost:8080/swagger-ui.html
- H2 콘솔: http://localhost:8080/h2-console (JDBC URL `jdbc:h2:mem:point` / User `sa` / Password 없음)
